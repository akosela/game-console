THIEF: THE DARK PROJECT (1998) / DARKSIM -- CONSOLE COMMAND REFERENCE
==============================================================================

  Dir      Campaign / mod           Developer              Released
  thief    Thief: The Dark Project  Looking Glass Studios  1998
  fms      The Black Parade         Feuillade Industries   2023
  darksim  DarkSim                  Andy Kosela            2026-

IMPORTANT:
The exact console command registry belongs to the executable being run:
THIEF.EXE, DROMED.EXE, or a NewDark-patched equivalent.

For an EXACT list from the executable/build you are using, run:

  dump_cmds thief_commands.txt

This writes the registered command list, with Looking Glass descriptions where
available. DromEd exposes a much larger registry than the normal game.

Some commands listed here are not directly relevant to DarkSim. They are
included for completeness because they document the broader command set and
internal functionality of the Dark Engine/NewDark environment on which
Thief: The Dark Project is built.

==============================================================================
1. CONSOLE BASICS
==============================================================================

Classic retail game
-------------------
The original game does not expose the large DromEd command prompt as openly as
System Shock 2. A reliable method is to bind edit_command in user.bnd:

  bind p edit_command

DarkSim uses ~.

Pressing the bound key opens the command editor. Historical Thief command
documentation notes that the command editor supports Emacs-style history and
editing keys such as Ctrl-P, Ctrl-N, and Ctrl-K.

DromEd game mode
----------------
When testing a mission in DromEd, Shift+; is commonly used to open the command
prompt. Many commands in sections 5 onward are primarily DromEd/debug commands
and may not exist or do anything useful in THIEF.EXE.

NewDark
-------
NewDark retains much of the original Dark Engine command architecture but can
add, remove, or alter commands depending on executable version. Use dump_cmds
on the exact executable if command availability matters.

Commands and arguments
----------------------
Arguments used in this reference:

  #  numeric argument
  <0|1>  off/on switch
  <name>  object, archetype, resource, or variable name
  <id>  numeric object ID
  <file>  filename
  <factor>  floating-point scale
  <x,y,z>  world coordinates

A leading "+" or "-" on an input command normally means press/release state.
For example:

  +crouch
  -crouch

This is mainly relevant to .bnd key bindings.

6. OBJECT CREATION / DESTRUCTION
==============================================================================

Normal THIEF.EXE game mode
--------------------------
Thief does not expose System Shock 2's `summon_obj` as a normal gameplay console
command. A known Thief Gold `dump_cmds` listing does not register `summon_obj`.

Do not infer command availability from System Shock 2 merely because both
games use the Dark Engine family. THIEF.EXE, DROMED.EXE, and Shock2.exe have
different command registries.

NewDark runtime scripting
-------------------------
NewDark Squirrel scripts can create objects while a mission is running.

For an object or AI that must be placed in the world, use BeginCreate,
Teleport, and EndCreate. For example, from an inventory frob script:

    local obj = Object.BeginCreate("Burrick");
    Object.Teleport(obj, vector(5, 0, 0), vector(0), message().Frobber);
    Object.EndCreate(obj);

Object.Create can be used when creation does not need the BeginCreate /
EndCreate sequence:

    local item = Object.Create("HealingPotion");

To put a newly created object into Garrett's inventory, create a Contains link
from the player to the object. When the script is attached to the player:

    local item = Object.Create("HealingPotion");
    Link.Create(LinkTools.LinkKindNamed("Contains"), self, item);

Use the internal archetype name from the loaded GameSys. A display string is
not necessarily the archetype name. Unique plot objects may require mission
links, scripts, quest variables, or original placement and therefore may not
function correctly when created at runtime.

DromEd
------
create_obj <archetype>
  Creates an object from an archetype in DromEd/editor command sets where the
  command is registered. It is not a general THIEF.EXE gameplay console
  replacement for `summon_obj`.

destroy_obj <name-or-id>
  Destroys an object by object name or object ID.

find_obj <name-or-id>
  Looks up an object by name or number.

edit_obj <name-or-id>
  Opens the object editor for an object.

copy_props_to <object>
  Copies properties from the selected object to another object. Use only when
  you understand the archetype/property relationship.

fixup_creature_phys
  Rebuilds/fixes creature physics dimensions and state from expected values.

find_lost_objs
  Finds lost/orphaned objects and attempts to assign/fix their archetypes.

deref_containees
  Removes references from contained objects. Low-level object-system command;
  use only for debugging/editor repair.

obj_histogram_popup
  Opens an object-usage histogram/list.

obj_alpha_popup
  Opens an alphabetically sorted object list.

For original Thief 1/TDP, the standard script module is normally:

trace_remove
  Removes a trace target/category.

trace_dump
  Dumps trace information.

  Dumps active trace information.

10. COMMAND DISCOVERY, CONSOLE, AND BINDING COMMANDS
==============================================================================

dump_cmds <filename>
  Dumps the executable's registered commands and built-in descriptions to a
  text file.
  Example:
    dump_cmds thief_commands.txt

This is the authoritative method for determining what your exact THIEF.EXE or
DROMED.EXE actually supports.

help
  Displays command help where available.

lg_help
  Looking Glass command-help facility in builds that expose it.

edit_command
  Opens the console command editor.

Typical binding:

  bind p edit_command

history_cmd
  Opens/uses command history.

last_command
  Stores or references the last console command in the original config system.

bind <key> "<command>"
  Binds a key to a command.
  Examples:
    bind p edit_command
    bind f10 screen_dump
    bind v dark_version

Because press/release commands can be bound directly, a binding such as:

  bind c +crouch

activates +crouch on press and -crouch on release.

==============================================================================
23. OBJECT-CREATION TROUBLESHOOTING
==============================================================================

If `summon_obj` is not recognized in THIEF.EXE:

- 1. This is expected; `summon_obj` is not a normal Thief gameplay console
  command.
- 2. Run dump_cmds on the executable you are actually using.
- 3. Remember that DromEd and THIEF.EXE expose different command sets.
- 4. Do not infer availability from System Shock 2; it uses the same engine
  family but has a different game executable and command registry.
- 5. Use NewDark Squirrel Object.Create / Object.BeginCreate for runtime
  object creation when building a mod or helper script.
- 6. Use DromEd's object-creation facilities when working in the editor.

If a NewDark runtime-created object fails or behaves incorrectly:

- 1. Use the exact Object Hierarchy spelling.
- 2. Verify the internal archetype in the currently loaded GameSys.
- 3. A string found inside DARK.GAM is not automatically a concrete archetype.
- 4. An abstract archetype may create an unusable object.
- 5. AI and world objects normally need a valid world position.
- 6. Plot objects may rely on links, scripts, quest variables, and original
  IDs.
- 7. Localized display names are separate from internal archetype names.

If a DromEd create/destroy operation fails:

- 1. Check the exact command registry with dump_cmds.
- 2. Verify the Object Hierarchy name or numeric object/archetype ID.
- 3. Check whether you selected an abstract category rather than a concrete
  descendant.
- 4. Save the mission before experimenting with destruction or creation.

==============================================================================
24. EXACT "ALL COMMANDS" WORKFLOW
==============================================================================

There is no single static internet list that is guaranteed to match every
Thief: The Dark Project executable, DromEd version, NewDark build, or patched
DarkSim executable.

For THIEF.EXE:

  1. Bind edit_command if necessary.
  2. Start the exact executable used by DarkSim.
  3. Open the command editor.
  4. Run:

       dump_cmds thief_commands.txt

  5. Inspect thief_commands.txt.

For DROMED.EXE:

  1. Start the exact DromEd build.
  2. Open the DromEd command prompt.
  3. Run:

       dump_cmds dromed_commands.txt

  4. Inspect dromed_commands.txt.

Expect the DromEd dump to be substantially larger than the retail game dump.

If you are patching or replacing THIEF.EXE, repeat the dump after executable
changes. That is the safest way to document commands added, removed, renamed,
or stripped by a specific build.

NOTE ON COMPLETENESS
--------------------
"All console commands" can mean several different things in Thief:

  A. Commands useful in ordinary Thief gameplay.
  B. Commands registered by THIEF.EXE but normally accessed only by binding
     edit_command.
  C. The much larger DromEd/editor/debug command registry.
  D. Dark Engine configuration variables usable in .cfg/.bnd files.
  E. NewDark-specific additions for a particular executable version.

This reference documents the useful game commands plus major Dark Engine and
DromEd command families. For literal executable-level completeness, the output
of dump_cmds from your exact binary is the final authority.

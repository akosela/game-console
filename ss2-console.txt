DARKSIM - SYSTEM SHOCK 2 — DOS (DARK OS) CONSOLE COMMAND REFERENCE
===================================================================

IMPORTANT
---------
The exact console command registry belongs to the game executable (ss2.exe /
NewDark build), not to shock2.gam.

For an EXACT list for your own executable/build, run this in the console if
supported:

  dump_cmds ss2_commands.txt

The engine writes its registered command list to a text file. This is the best
way to catch build-specific, undocumented, editor-only, or mod-added commands.

Some of the commands listed in this reference are not directly relevant to
DarkSim. They are included for completeness, however, as they help document
the broader command set and internal functionality of the Dark Engine/NewDark
environment on which System Shock 2 is built.

CONSOLE BASICS
--------------
Classic/NewDark:
  Open the in-game command line with the console key configured by the
  game/build.
  DarkSim uses ~.

Commands are generally case-insensitive.

Arguments in this file:
  #  numeric argument
  <0|1>  off/on switch
  <name>  object/archetype/resource name
  <id>  numeric object ID
  <slot>  quickslot number

A leading "+" on a bindable command usually means "active while key is held",
for
example +fire_weapon in a .bnd file.

==============================================================================
1. NORMAL GAMEPLAY / INPUT COMMANDS
==============================================================================

show_version
  Displays the Dark Engine / SS2 version while in game mode.

psi_power <1..5>
  Switches the active Psi tier.

select_psipower
select_psi_power
  Opens/selects the Psi power interface. The exact spelling exposed by a build
  can
  vary; select_psipower is the classic documented gameplay form.

cycle_weapon <1|-1>
  Cycles to the next or previous equippable weapon.
  Example:
  cycle_weapon 1
  cycle_weapon -1

fire_weapon <0|1>
  Starts/stops firing the current weapon.
  Normally bound as:
  +fire_weapon

reload_gun
  Reloads the currently equipped firearm from compatible inventory ammunition.

swap_guns
  Swaps the primary and secondary/current weapon selection where supported.

wpn_setting_toggle
  Toggles the alternate setting/fire mode of the current weapon.

cycle_ammo
  Cycles compatible ammunition types for the current weapon.

equip_weapon <object-name>
  Searches inventory for the named weapon/archetype and equips it.
  Example:
  equip_weapon assault rifle

select_gun <name-or-id>
  Developer-level weapon selection command. Selects/readies a gun by object
  name
  or object number where the current build exposes it.

use_obj <object-name>
  Uses an inventory object by archetype/name.
  Example:
  use_obj med patch

interface_use
  Performs the inventory/interface "use" action on the selected item.

quickbind <slot>
  Assigns the currently selected item/action to a quickslot.

quickuse <slot>
  Activates the specified quickslot.

shock_jump_player
  Makes the player jump.

toggle_mouse
  Switches between mouselook/game mode and cursor/interface mode.

look_cursor
  Puts the cursor into look/query mode.

query <0|1>
  Turns query cursor mode off/on.

split <0|1>
  Turns split cursor mode off/on.

frob_toggle
  Toggles the current frob/interface interaction mode.

frob_object
  Frobs/uses the currently selected world object.

frob_object_inv
  Frobs/uses the selected object, including an inventory object where
  applicable.

drag_and_drop <0|1>
  Controls basic drag-and-drop state. Mostly an internal UI/input command.

drag_and_drop_frob <0|1>
  Internal drag-and-drop/frob interaction command.

drag_and_drop_mode <0|1>
  Internal drag-and-drop mode switch.

toggle_inv
  Opens/closes the inventory panel.

toggle_compass
  Toggles the compass display.

msg_history
  Opens/toggles message history.

play_unread_log
  Plays an unread audio log/message.

stop_email
  Stops the currently playing e-mail/audio log.

clear_teleport
  Clears the existing Psi teleport marker.

quicksave
  Quick-saves to the current quicksave location.

quickload
  Quick-loads the current quicksave.

save_game
  Opens/executes the normal save-game path depending on build/UI state.

load_game
  Opens/executes the normal load-game path depending on build/UI state.

main_menu
  Returns/opens the main menu.

sim_menu
  Opens the simulation/game menu.

open_mfd <overlay-number>
  Opens an MFD/overlay by internal overlay number.

Useful SS2 upgrade overlays:
  open_mfd 35  Stats upgrade interface
  open_mfd 36  Tech upgrade interface
  open_mfd 37  Weapon upgrade interface
  open_mfd 38  Psi upgrade interface
  open_mfd 20  O/S upgrade interface

overlay_toggle <overlay-number>
  Toggles an overlay/MFD by its internal number. Developer-oriented.

==============================================================================
2. CHEAT / PLAYER-STATE COMMANDS
==============================================================================

add_pool <number>
  Adds Cyber Modules to the player's module pool.
  Example:
  add_pool 50

psi_full
  Refills/maxes the player's current Psi points.

ubermensch
  Sets the player to very high/maximal normal stats, weapon skills and tech
  skills.
  It does not necessarily grant every Psi tier/power.

add_hp <number>
  Adds health where this command is available in the current build.

set_psi_points <number>
  Sets current Psi points. Present in developer/editor command sets;
  availability in
  the normal retail executable varies by build.

set_max_psi <number>
  Sets maximum Psi points. Developer/editor oriented and build-dependent.

enable_cheats
  Enables engine cheat facilities in builds that expose the command.

unfly
  Toggles/disables a flying state in builds that expose player flight/debug
  movement.

unstick_player
  Attempts to move the player out of obstructing/colliding geometry.
  Primarily associated with newer NewDark builds.

teleport_player <x,y,z>
  Teleports the player to world coordinates.
  Example:
  teleport_player -34,-23,3

log_player_pos
  Prints/logs the player's current world coordinates.

log_obj_pos <object>
  Logs position information for an object where supported.

halt_player
  Stops/freezes player movement/control state. Developer/debug command.

scale_player_speed <factor>
  Scales player movement speed in builds where enabled.
  Example:
  scale_player_speed 1.5

time_passes <0|1>
  Controls whether simulation time advances. Mostly developer/editor
  functionality.

scale_sim_time <factor>
  Scales simulation speed.
  Example:
  scale_sim_time 0.5
  Known to be useful in editor/debug contexts; normal-game behavior is
  build-dependent.

show_sim_time
  Displays/logs simulation timing information.

==============================================================================
3. OBJECT CREATION / DESTRUCTION
==============================================================================

summon_obj <archetype-name-or-object-code>
  Creates an instance of an object/archetype near the player.

Examples:
  summon_obj pistol
  summon_obj shotgun
  summon_obj assault rifle
  summon_obj psi amp
  summon_obj wrench
  summon_obj big nanite pile
  summon_obj nav marker

Important:
  - Names with spaces are entered as ordinary command arguments; quoting is
  normally
  unnecessary in the classic console.
  - summon_obj operates on object/archetype names from the loaded GameSys.
  - A valid-looking display name is not always the actual archetype name.
  - Spawning mission-critical objects, AI, trainers, keys, markers, or
  scripted devices
  can interfere with scripts/quest state. Save first.
  - Some archetypes spawn partially initialized, unresearched, unloaded,
  inert, or with
  odd/default properties.

summon_obj_at <name> [...]
  Developer variant that creates an object at an explicitly supplied location
  or
  editor/object position. Exact parameter format varies by engine build.

destroy_obj <name-or-id>
  Destroys an object by object ID/name in builds exposing the command.
  Use with care: deleting mission-critical objects can break scripts.

12. COMMANDS COMMONLY SEEN IN BIND FILES
==============================================================================

A .bnd line uses the form:

  bind <key> "<command>"

Examples:

  bind r reload_gun
  bind k toggle_compass
  bind l msg_history
  bind u play_unread_log
  bind o wpn_setting_toggle
  bind ins "summon_obj big nanite pile"
  bind mouse_wheel_up "cycle_weapon 1"
  bind mouse_wheel_down "cycle_weapon -1"

Movement commands often appear with "+" because they are active while held,
for example:

  +walkfast
  +backfast
  +turnleftfast
  +turnrightfast
  +leanleft
  +leanright
  +creepon
  +jump
  +fire_weapon

These are bindable input commands rather than one-shot cheat commands.

==============================================================================
12. CONFIG-VARIABLE CHEATS (NOT ONE-SHOT CONSOLE COMMANDS)
==============================================================================

Historical SS2 builds also recognize configuration variables such as:

undead
  God/invulnerability-style cheat in builds where enabled.

gun_degrade_rate 0
  Disables weapon degradation by setting degradation rate to zero.

no_spawn
  Suppresses normal monster respawning in builds where the variable is
  honored.

These are often placed in user.cfg rather than typed as normal gameplay
commands.

==============================================================================
12. TROUBLESHOOTING summon_obj
==============================================================================

If:
  summon_obj <name>

does not work:

1. Try the exact internal archetype spelling, not the localized display name.
2. Try console autocomplete if your build provides it.
3. Inspect object-name strings/resources or the GameSys object hierarchy.
4. Remember that underscores, spaces, punctuation and abbreviations matter.
5. Some objects have a human-readable display name that differs from the
archetype.
6. Some archetypes are abstract parents and may not instantiate usefully.
7. Some unique mission objects cannot be recreated correctly from their
archetype alone.
8. If you need the object ID of an already placed instance, use
editor/object-inspection
  tools rather than guessing from the display name.

For your supplied shock2.gam, strings directly confirm names including:
  Pistol
  Shotgun
  Assault Rifle
  Laser Pistol
  Psi Amp
  PsiSword
  Wrench
  Nav Marker
  EXP Cookies
  Nanites

==============================================================================
12. EXACT "ALL COMMANDS" WORKFLOW FOR YOUR OWN SS2.EXE
==============================================================================

Because NewDark, editor builds and patched executables register different
commands,
the authoritative procedure is:

  1. Start your exact ss2.exe.
  2. Open the console.
  3. Run:
  dump_cmds ss2_commands.txt
  4. Exit the game.
  5. Open ss2_commands.txt from the game directory.

That generated file is more authoritative than any internet list because it is
created
from the exact executable you are running.

If dump_cmds is unavailable, console autocomplete can still expose many
registered
commands, but it is less convenient for creating a complete reference.

NOTE ON COMPLETENESS
--------------------
"All console commands" can mean three different things in SS2:

  A. Commands useful in the normal game.
  B. Every command registered by the Dark/NewDark engine, including
  renderer/debug,
  script, network and editor internals.
  C. Build-specific console variables and editor/debug commands.

This file includes A comprehensively and includes known B command families,
but
the exact executable-generated result from dump_cmds is the final authority
for B.
Console variables (CVars) are a separate namespace and are not exhaustively
enumerated
here because they are build-specific and are not all executable commands.

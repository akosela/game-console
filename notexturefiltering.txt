NOTEXTUREFILTERING -- SHARP / PIXELATED TEXTURE REFERENCE
==============================================================================

SCOPE
------------------------------------------------------------------------------
Games covered: Duke Nukem 3D using EDuke32, Quake, Quake II, Unreal,
Unreal Tournament, Half-Life, Deus Ex, Gothic, Gothic II, Gothic 3,
Morrowind, Oblivion, Skyrim, Fallout 3, Vietcong, Red Faction, Thief:
The Dark Project using NewDark, and System Shock 2 using NewDark. Goal:
disable bilinear/trilinear/anisotropic texture filtering so texels stay
visibly sharp and pixelated instead of being smoothed together.
Remaster-only settings are intentionally excluded.

==============================================================================
0. WHAT 'NO TEXTURE FILTERING' MEANS
==============================================================================

Nearest-neighbor, point-sampled, or 'nearest' filtering selects one texel
instead of blending neighboring texels. This gives enlarged low-resolution
textures hard pixel edges.
Disabling anisotropic filtering is NOT the same thing. A game can have AF
disabled while still using bilinear filtering and therefore still look
blurred.
Mipmapping is also separate. Nearest filtering can still be combined with
nearest-selected mip levels. Disabling mipmaps entirely gives the harshest
pixelated look, but usually causes strong shimmering and aliasing at a
distance.

==============================================================================
0.1. DGVoodoo2 METHOD FOR GAMES WITHOUT A NATIVE SWITCH
==============================================================================

Several Direct3D games in this list do not expose a verified native
nearest-neighbor option. For those games the cleanest general method is
dgVoodoo2, while still running the original game executable.
In dgVoodoo2 Control Panel, select the game's configuration and open the
DirectX tab. Set:

  Filtering: Force point sampled

This forces nearest-neighbor texture sampling. Do not confuse this with the
General-tab Resampling setting; Resampling controls final image scaling, not
the filtering used on 3D world textures.
For the most aggressively pixelated result, dgVoodoo2 can also disable
mipmapping. This is optional and normally not recommended because distant
surfaces will shimmer heavily.

Optional:

  Mipmapping: Disabled

Use the wrapper DLL appropriate to the game's DirectX version. Direct3D 1-7
games normally use the DirectDraw/D3DImm wrapper files; Direct3D 8 games use
D3D8.dll; Direct3D 9 games use D3D9.dll.
Forced point sampling can reveal seams, blocky lightmaps, halos around masked
textures, and pixelated HUD elements. Those are expected side effects of
overriding filtering globally.

==============================================================================
1. DUKE NUKEM 3D (1996) -- EDUKE32
==============================================================================

IMPORTANT: Config files:
  Enter r_texfilter and r_anisotropy in the console or use the Video Setup
  menu.
  EDuke32 stores persistent settings in its selected configuration file,
  normally eduke32.cfg; avoid editing that file while the game is running.

r_texfilter 0
  Sets EDuke32's texture filter to Nearest, giving point-sampled pixels.

r_anisotropy 0
  Disables anisotropic filtering. This is not strictly required for the
  nearest look, but keeps the filtering configuration unambiguous.

The menu equivalent is Video Setup -> OpenGL -> Texture Filter -> Nearest.
EDuke32 exposes six filter modes. Nearest is the basic unfiltered mode.
Nearest-MM-Nearest and Nearest-MM-Linear keep nearest texel sampling but still
use mipmapping.

Recommended sharpest setup:

  r_texfilter 0
  r_anisotropy 0

==============================================================================
2. QUAKE (1996) -- MARK V
==============================================================================

IMPORTANT: Config files:
  Preferred manual overrides: id1\autoexec.cfg, or autoexec.cfg in the
  active mod directory. Put gl_texturemode, gl_smoothmodels, r_particles,
  and r_wateralpha there.
  id1\config.cfg is engine-generated and may be rewritten by Mark V; use
  autoexec.cfg for deliberate manual overrides.

Mark V v1099 Revision 4 is the selected Quake source port. The normal Windows
Mark V build is a DirectX 9 build using MH's Direct3D wrapper. Despite the
historic GLQuake-style cvar names, hardware-renderer controls such as
gl_texturemode are retained and work in the DirectX build.

For the sharpest point-sampled map textures:

  gl_texturemode GL_NEAREST
  gl_smoothmodels 0

Mark V describes GL_NEAREST as the "crunchy pixels" texture mode for map
textures. gl_smoothmodels 0 disables smoothing of textures used on models, so
monster and weapon skins are not left smoothed while the world is pixelated.

For a classic GLQuake-style look with point-sampled texels but smooth
transitions between mip levels, use:

  gl_texturemode GL_NEAREST_MIPMAP_LINEAR

GL_NEAREST_MIPMAP_LINEAR disables bilinear filtering inside each mip level,
but linearly blends between adjacent mip levels. It therefore keeps sharp
texels while reducing visible mip-band transitions and distant shimmering.
Use GL_NEAREST instead when absolutely no texture filtering is desired.

Additional classic-presentation settings:

r_particles 2
  Uses square/chunky particles instead of rounded particles.

r_wateralpha 0.5
  Makes water 50% transparent. Transparent water requires compatible map
  visibility data. Mark V can load external .vis files for the original
  maps; .lit files provide colored lighting and do not enable water
  visibility.

Recommended strict no-filtering setup:

  gl_texturemode GL_NEAREST_MIPMAP_LINEAR
  gl_smoothmodels 0
  r_particles 2
  r_wateralpha 0.5

Mark V also includes a WinQuake-style software renderer. That renderer already
has the classic point-sampled software look and does not need gl_texturemode.

==============================================================================
3. QUAKE II (1997) -- YAMAGI QUAKE II / ORIGINAL OPENGL
==============================================================================

IMPORTANT: Config files:
  Preferred manual override: baseq2\autoexec.cfg. Put gl_texturemode and
  r_2D_unfiltered there; add r_videos_unfiltered if wanted.
  baseq2\config.cfg is engine-managed and may be rewritten. Yamagi may keep
  its writable baseq2 directory in the user-data location.

Yamagi Quake II retains the classic gl_texturemode control across its OpenGL
renderers.

gl_texturemode GL_NEAREST
  Uses nearest-neighbor sampling with no mipmaps. Yamagi's official cvar
  documentation explicitly defines GL_NEAREST as no filtering.

For point-sampled texels while keeping nearest-selected mip levels:

  gl_texturemode GL_NEAREST_MIPMAP_NEAREST

For a consistently pixelated Yamagi interface as well as world textures:

  r_2D_unfiltered 1

This disables bilinear filtering on 2D elements such as menus and the HUD.
It is separate from gl_texturemode, which controls the 3D OpenGL textures.

Optional for videos:

  r_videos_unfiltered 1

The original Quake II OpenGL renderer supports the same GL_NEAREST and
GL_NEAREST_MIPMAP_NEAREST texture modes. The original software renderer is
naturally unfiltered.

Recommended Yamagi setup:

  gl_texturemode GL_NEAREST
  r_2D_unfiltered 1

4. UNREAL (1998)
==============================================================================

IMPORTANT: Config files:
  Run the bNoSmooth command from the in-game console after a map loads.
  For convenience, put a key binding that runs the command in
  System\User.ini; the command may still need to be re-run after level
  transitions.

For the original Unreal Engine 1 texture system, the preferred way to remove
smoothing without globally destroying lightmap filtering is to set the native
bNoSmooth properties on loaded textures and actors.

Texture.bNoSmooth disables smoothing for texture surfaces. Actor.bNoSmooth
disables smoothing for textures drawn on actors, including meshes and sprites.

set texture bNoSmooth true | set actor bNoSmooth true
  Applies the no-smoothing flags to currently loaded Texture and Actor
  objects. This is the preferred hardware-renderer method for the
  sharp/pixelated look.

Because new Texture and Actor objects are loaded with each map, the
command may need to be executed again after every level transition.

Useful key binding:

  set input p set texture bNoSmooth true | set actor bNoSmooth true

Then press P after loading a new level.

The original Software Rendering device is another valid option and
already has the classic point-sampled appearance.

IMPORTANT:
NoFiltering=True is NOT the preferred method here.

Enhanced UTGLR/OldUnreal renderers do expose NoFiltering=True, and
it really does disable filtering globally. However, it is a broad
renderer debug option. It also changes filtering of lightmaps and
other rendering paths, which can make lighting look very blocky.

bNoSmooth is the more targeted UE1 mechanism when the goal is sharp
base textures and actor skins while retaining smooth lightmaps.

5. UNREAL TOURNAMENT (1999)
==============================================================================

IMPORTANT: Config files:
  Put the persistent key binding in System\User.ini, for example the P=
  binding shown below.
  The bNoSmooth command acts on currently loaded objects, so press the bound
  key again after a map transition if needed.

UT99 uses the same Unreal Engine 1 Texture.bNoSmooth and Actor.bNoSmooth
properties. For hardware rendering, use the console command rather than
relying on the renderer-wide NoFiltering option.

set texture bNoSmooth true | set actor bNoSmooth true
  Disables smoothing on currently loaded world textures and actor textures.

A convenient persistent binding in User.ini is:

  P=set texture bNoSmooth true | set actor bNoSmooth true

Press the bound key after entering a new map if newly loaded
textures or actors are smooth again.

The original Software Rendering device is also naturally
point-sampled.

NoFiltering=True in enhanced UTGLR/OldUnreal renderers is broader.
It disables filtering globally, including lightmap/shading paths,
so it is not equivalent to simply setting bNoSmooth on game
textures and actors.

6. HALF-LIFE (1998) -- GOLDSRC
==============================================================================

IMPORTANT: Config files:
  Preferred persistent override: valve\autoexec.cfg. Put gl_texturemode
  there.
  valve\config.cfg is engine-generated and may be rewritten, so autoexec.cfg
  is safer for a deliberate manual texture-mode override.

gl_texturemode GL_NEAREST
  Uses nearest-neighbor texture sampling in the GoldSrc OpenGL renderer.

GL_NEAREST is the strongest setting: sharp texels and no mipmaps. For nearest
texels while retaining mip levels, try:

  gl_texturemode GL_NEAREST_MIPMAP_NEAREST

If the installed GoldSrc build resets the value, put the command in
autoexec.cfg. The classic software renderer also has an inherently pixelated
appearance.

7. DEUS EX (2000)
==============================================================================

IMPORTANT: Config files:
  Run the bNoSmooth command from the in-game console after a map loads.
  For a reusable key, store a binding in System\User.ini; reapply it when
  newly loaded textures or actors become filtered again.

Deus Ex is based on Unreal Engine 1 and uses the same native Texture.bNoSmooth
and Actor.bNoSmooth properties. The targeted console method is therefore
preferable to renderer-wide filtering overrides.

set texture bNoSmooth true | set actor bNoSmooth true
  Sets the no-smoothing flags on the currently loaded Texture and Actor
  objects.

If the command is rejected by the current Deus Ex configuration,
enable the normal Deus Ex cheat/developer console path first.

Reapply the command after a map transition if new textures or
actors appear filtered.

The built-in Software Rendering device is the original-engine
alternative, although it can be inconvenient on current Windows
systems.

Enhanced Unreal Engine 1 renderers may expose NoFiltering=True.
That option is valid as a global renderer switch, but it is much
broader than bNoSmooth and can make lightmaps/shadows blocky.

8. GOTHIC (2001)
==============================================================================

IMPORTANT: Config files:
  Native AF setting: Gothic\System\Gothic.ini, using
  zTexAnisotropicFiltering=0.
  For true point sampling, place the dgVoodoo wrapper files and
  dgVoodoo.conf beside Gothic.exe in Gothic\System, then set Force point
  sampled in dgVoodoo.

Gothic.ini contains zTexAnisotropicFiltering, but setting it to 0 only
disables anisotropic filtering. It does NOT disable the engine's ordinary
bilinear texture sampling.

Keep AF disabled:

  zTexAnisotropicFiltering=0

No verified stock ZenGin console/INI option switches all textures to
nearest-neighbor sampling.
For a true pixelated look while keeping the original Gothic executable, use
dgVoodoo2 and set DirectX -> Filtering to Force point sampled.
Gothic uses an old Direct3D path, so use the dgVoodoo DirectDraw/D3D wrapper
files appropriate to the installation.

9. GOTHIC II (2002)
==============================================================================

IMPORTANT: Config files:
  Native AF setting: Gothic II\System\Gothic.ini, using
  zTexAnisotropicFiltering=0.
  For true point sampling, place the dgVoodoo wrapper files and
  dgVoodoo.conf beside Gothic2.exe in the System directory, then set Force
  point sampled.

As in Gothic 1, this original Gothic.ini setting disables only AF:

  zTexAnisotropicFiltering=0

It does not turn bilinear filtering into nearest-neighbor filtering.
For actual point-sampled textures with the original Gothic II executable, use

  DirectX -> Filtering -> Force point sampled

Use the DirectDraw/D3D wrapper files for the original ZenGin Direct3D
renderer. If the HUD or alpha-tested foliage develops hard borders, that is a
normal side effect of forcing point sampling.

11. THE ELDER SCROLLS III: MORROWIND (2002)
==============================================================================

IMPORTANT: Config files:
  There is no vanilla Morrowind.ini nearest-neighbor switch.
  Place the x86 dgVoodoo D3D8.dll and dgVoodoo.conf beside Morrowind.exe,
  then configure Force point sampled in dgVoodoo.

The original Morrowind engine uses filtered textures and has no verified
vanilla INI switch equivalent to OpenMW's nearest min/mag filter settings.
For the ORIGINAL Morrowind.exe, use dgVoodoo2 with the Direct3D 8 wrapper:

  copy the appropriate x86 D3D8.dll wrapper
  DirectX -> Filtering -> Force point sampled

This preserves the original game engine while overriding its sampler behavior.
Do not use OpenMW settings in this section. OpenMW is a different engine. Its
nearest-filter options are intentionally excluded because this file is
documenting the original Morrowind executable.
A texture-replacement workaround such as Morrowind Pixellized can imitate an
unfiltered look, but a sampler override is cleaner when it works.

14. FALLOUT 3 (2008)
==============================================================================

IMPORTANT: Config files:
  FalloutPrefs.ini can control anisotropy/mipmap-related values, but it has
  no native nearest-neighbor switch.
  Place the x86 dgVoodoo D3D9.dll and dgVoodoo.conf beside Fallout3.exe,
  then configure Force point sampled in dgVoodoo.

Fallout 3 uses Direct3D 9. Its original INI files expose texture quality,

Use the original Fallout3.exe through dgVoodoo2's Direct3D 9 wrapper:

  use the x86 D3D9.dll wrapper
  DirectX -> Filtering -> Force point sampled

Keep mipmapping App driven initially. FalloutPrefs.ini contains settings such

Fallout 3 engine does not expose a clean per-material nearest switch.

16. RED FACTION (2001)
==============================================================================

IMPORTANT: Config files:
  r_nearest and r_trilinearfiltering are in-game console commands; no
  external wrapper or INI edit is required for the documented method.

r_nearest
  Toggles nearest-neighbor texture filtering in the original Red Faction
  client.

This is a genuine base-game console command, not a Dash/Pure/Alpine Faction
addition.
Because r_nearest is a toggle, enter it once to switch nearest filtering on
and enter it again to return to the normal filtering state.
r_trilinearfiltering
  Toggles trilinear filtering. If trilinear filtering was explicitly enabled,
  leave it off when using the nearest look.

The important command for the pixelated look is r_nearest.

17. THIEF: THE DARK PROJECT (1998) -- NEWDARK
==============================================================================

IMPORTANT: Config files:
  Persistent setting: cam_ext.cfg in the game directory. Set tex_filter_mode
  0 there and remove a leading semicolon if the line is commented.

NewDark exposes the texture-filter mode directly in cam_ext.cfg. This is the
preferred method for a sharp, pixelated Thief installation.

Open cam_ext.cfg and set:

  tex_filter_mode 0

NewDark defines the values as:
  - 0 — no filtering
  - 1 — linear filtering
  - 2, 4, 8, 16 — anisotropic filtering using that sample count

If the line is commented with a semicolon, remove the semicolon so the setting
is active.
Example:

  ;tex_filter_mode 16

becomes:

  tex_filter_mode 0
NewDark applies this broadly, so lightmaps can also become blocky. This is
expected and is one reason NewDark with filtering disabled does not look
identical to the original 1998 software renderer.
Do not merely disable trilinear filtering while leaving tex_filter_mode at 16.
That still leaves anisotropic/linear texture filtering active.

18. SYSTEM SHOCK 2 (1999) -- NEWDARK
==============================================================================

IMPORTANT: Config files:
  Persistent setting: cam_ext.cfg in the game directory. Set tex_filter_mode
  0 there and remove a leading semicolon if the line is commented.

System Shock 2 NewDark uses the same explicit filtering control.

Open cam_ext.cfg and set:

  tex_filter_mode 0

The NewDark comment normally describes the modes directly:
  - 0 — none
  - 1 — linear
  - 2, 4, 8, 16 — anisotropic sample count

A common NewDark default is tex_filter_mode 16. Change 16 to 0 and remove the
leading semicolon if the setting is commented out.
Example:

  ;tex_filter_mode 16

becomes:

  tex_filter_mode 0
This produces the crisp, visibly pixelated world-texture look. As with Thief,
some lightmaps and 2D assets can also look more blocky because the filter
setting is broad.

19. MECHWARRIOR 3 (1999)
==============================================================================

IMPORTANT: Config files:
  Select Software Render from Main Menu -> Options -> Graphics -> Video
  Device.
  This method uses the game's own saved graphics choice; no manual CFG/INI
  edit is required.

MechWarrior 3 has a native Software Render video device. This is the preferred
original-game route for a sharp, point-sampled appearance because no verified
stock Direct3D option was found that globally forces nearest-neighbor
filtering.
MicroProse's own patch documentation describes the Software Render device as a
normal selectable graphics option.

Original-game method:

  Main Menu -> Options -> Graphics
  Video Device -> Software Render
  Accept

Changing the Video Device causes MechWarrior 3 to exit; restart the game for
the new renderer to take effect.
The software renderer is the game's GameZ renderer. Its software textured span
path samples individual source texels rather than relying on the hardware
bilinear filtering path, which gives the desired hard-edged pixelated
presentation.
The Software Render component must have been installed. If it was omitted
during a custom installation, reinstall/add that component before trying to
select the renderer.
The original game also has a Direct3D 6 hardware renderer, but no native
MechWarrior 3 setting was verified for changing its sampler from bilinear to
nearest-neighbor.
dgVoodoo2 can theoretically force point sampling for old Direct3D games, but
it is NOT the preferred recommendation for MechWarrior 3. Modern testing has
found compatibility problems between dgVoodoo and MW3's software-composited
cockpit/HUD path, including mission-load crashes.
Therefore, if the goal is specifically the unfiltered, pixelated look, use the
original Software Render device first.

Recommended:

  Video Device -> Software Render

21. FILTERING VS MIPMAPPING
==============================================================================

If the main goal is sharp pixels up close but stable distant surfaces, keep
mipmaps and use nearest filtering. The useful Quake-style equivalent is
GL_NEAREST_MIPMAP_NEAREST.
If the goal is the most aggressively raw texture presentation possible, use
nearest filtering with no mipmaps. This maximizes hard pixel edges but causes
moire patterns, crawling, and shimmer on distant floors and walls.
For NewDark, tex_filter_mode 0 is the documented no-filtering mode. There is
no separate requirement to set an anisotropic value to zero.
